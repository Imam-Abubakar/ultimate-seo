# Plain HTML / Static Sites (no framework)

Hand-written HTML is the easiest thing in the world for crawlers: what you write is what they get. The work is consistency — every page needs its own complete `<head>`, and robots/sitemap/llms files must be maintained by hand or with this skill's `generate_sitemap.py`. This file is also the fallback for any unknown stack: the `<head>` below is what every framework should ultimately render.

## Detect

- `index.html` at root or in `public/`/`docs/`/`site/`, no `package.json` framework, or a `package.json` with only tooling (Tailwind, a bundler, `serve`).
- Hosting hints: `CNAME` (GitHub Pages), `netlify.toml`, `vercel.json`, `_redirects`, `_headers`, `.htaccess` (Apache), `nginx.conf`.
- If pages are generated by a build tool (Vite multi-page, Parcel), audit the built output (`dist/`), but edit the source HTML.

## Where things go

| Concern | Location |
|---|---|
| Metadata | each `*.html` `<head>` |
| robots.txt, sitemap.xml, llms.txt, favicon.ico, site.webmanifest | site root (same dir as `index.html`) |
| OG image | `/og/default.png` (1200×630), per-page images optional |
| JSON-LD | `<script type="application/ld+json">` in each page's `<head>` |
| Redirects / 404 | host config (see below) + `404.html` |

## Site config (for hand-written sites)

There's no code to centralize config in, so make the playbook the source of truth: put a "Site facts" block at the top of `ULTIMATE-SEO.md` (origin, name, default description, OG image, locale, social handles) and keep all pages consistent with it. If there are more than ~10 pages, recommend the partials approach below or a lightweight SSG (Eleventy) — duplicating heads by hand drifts.

## The ideal `<head>`

```html
<!doctype html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">

  <title>Handmade Oak Desks, Built to Order · Example Studio</title>
  <meta name="description" content="Solid oak desks made to your measurements in Portland. Free design consult, 8-week build, lifetime joinery warranty.">
  <link rel="canonical" href="https://www.example.com/desks/">

  <!-- Open Graph -->
  <meta property="og:type" content="website">
  <meta property="og:site_name" content="Example Studio">
  <meta property="og:locale" content="en_US">
  <meta property="og:title" content="Handmade Oak Desks, Built to Order">
  <meta property="og:description" content="Solid oak desks made to your measurements in Portland.">
  <meta property="og:url" content="https://www.example.com/desks/">
  <meta property="og:image" content="https://www.example.com/og/desks.png">
  <meta property="og:image:width" content="1200">
  <meta property="og:image:height" content="630">
  <meta property="og:image:alt" content="A finished oak desk in a sunlit studio">
  <meta name="twitter:card" content="summary_large_image">

  <!-- Icons & app -->
  <link rel="icon" href="/favicon.ico" sizes="48x48">
  <link rel="icon" href="/icon.svg" type="image/svg+xml">
  <link rel="apple-touch-icon" href="/apple-touch-icon.png">
  <link rel="manifest" href="/site.webmanifest">
  <meta name="theme-color" content="#1f2937">

  <!-- Performance: preload the LCP image and self-hosted font -->
  <link rel="preload" as="image" href="/img/desk-hero.avif" type="image/avif" fetchpriority="high">
  <link rel="preload" as="font" href="/fonts/inter-var.woff2" type="font/woff2" crossorigin>
  <link rel="stylesheet" href="/css/site.css">

  <!-- Structured data -->
  <script type="application/ld+json">
  {
    "@context": "https://schema.org",
    "@type": "BreadcrumbList",
    "itemListElement": [
      { "@type": "ListItem", "position": 1, "name": "Home", "item": "https://www.example.com/" },
      { "@type": "ListItem", "position": 2, "name": "Desks", "item": "https://www.example.com/desks/" }
    ]
  }
  </script>

  <script src="/js/site.js" defer></script>
</head>
```

Keep the URL form the site already uses. If existing pages and inbound links use `/menu.html`, canonicalize to `/menu.html`; switching to clean URLs (`/menu`) is only worth it with 301s from every old URL, and only when you control the host's rewrite rules.

Rules: every URL absolute in canonical/OG/JSON-LD; canonical self-references the exact URL form you serve (trailing slash, `www`, `https`); unique title + description per page; no `<meta name="keywords">`; analytics scripts `async`/`defer` and placed after critical CSS.

## Body: semantics and performance

```html
<body>
  <a class="skip-link" href="#main">Skip to content</a>
  <header><nav aria-label="Primary"><a href="/">Example Studio</a> <a href="/desks/">Desks</a> …</nav></header>
  <main id="main">
    <h1>Handmade oak desks, built to order</h1>
    <img src="/img/desk-hero.avif" alt="Oak desk with dovetail drawers" width="1600" height="900" fetchpriority="high">
    …
    <img src="/img/joinery.avif" alt="Close-up of hand-cut dovetails" width="800" height="600" loading="lazy" decoding="async">
  </main>
  <footer>… address, contact, key links …</footer>
</body>
```

Use `<picture>` with AVIF/WebP + JPEG fallback for photos; `width`/`height` on every image prevents CLS. Never lazy-load the LCP image.

## robots.txt

Start from `assets/robots.txt` in this skill. Minimum:

```
User-agent: *
Allow: /

Sitemap: https://www.example.com/sitemap.xml
```

## sitemap.xml

Generate from the files instead of writing by hand:

```bash
python3 <skill-dir>/scripts/generate_sitemap.py . --base-url https://www.example.com --lastmod git
```

It walks HTML files, skips pages with `noindex` or a canonical pointing elsewhere, maps `about/index.html` → `/about/`, skips error pages like `404.html`, and writes `sitemap.xml` into the directory. `--lastmod git` uses each file's last commit date (honest for hand-written HTML); the default omits `lastmod` rather than faking it. Add `--no-trailing-slash` if the host serves `/about` instead of `/about/`. URL form follows the site itself: if pages link to `menu.html`, the sitemap uses `/menu.html` (override with `--html-extension keep|strip`), and each page's own absolute canonical always wins. Re-run it whenever pages change — document the command in `ULTIMATE-SEO.md` and, if there's a CI/deploy step, add it there.

Hand-written format if needed:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
  <url><loc>https://www.example.com/</loc><lastmod>2026-10-01</lastmod></url>
  <url><loc>https://www.example.com/desks/</loc><lastmod>2026-09-14</lastmod></url>
</urlset>
```

## llms.txt, icons, manifest

- `llms.txt` from `assets/llms.txt`, filled with real page links.
- `site.webmanifest`:

```json
{
  "name": "Example Studio",
  "short_name": "Example",
  "icons": [
    { "src": "/icon-192.png", "sizes": "192x192", "type": "image/png" },
    { "src": "/icon-512.png", "sizes": "512x512", "type": "image/png" },
    { "src": "/icon-512-maskable.png", "sizes": "512x512", "type": "image/png", "purpose": "maskable" }
  ],
  "theme_color": "#1f2937",
  "background_color": "#ffffff",
  "display": "standalone",
  "start_url": "/"
}
```

## 404 and redirects by host

| Host | 404 | Redirects (e.g. apex → www, old URLs) |
|---|---|---|
| GitHub Pages | `404.html` at root (served with 404 status) | No server redirects; use DNS/`CNAME` for host; `jekyll-redirect-from` style meta-refresh is a weak fallback |
| Netlify | `404.html` | `_redirects`: `/old /new 301` ; domain settings for apex/www |
| Vercel | `404.html` | `vercel.json` `"redirects": [{ "source": "/old", "destination": "/new", "permanent": true }]` |
| Cloudflare Pages | `404.html` | `_redirects` file |
| Apache | `ErrorDocument 404 /404.html` | `.htaccess` `Redirect 301 /old /new` or `RewriteRule` for host canonicalization |
| Nginx | `error_page 404 /404.html;` | `return 301 https://www.example.com$request_uri;` server block |

Make the 404 page `noindex` and helpful (search, key links).

## Shared partials without a framework

If there are many pages with duplicated heads/navs, options in increasing effort:
1. Keep hand-written, but add `seo_audit.py` to CI to catch drift (duplicate titles, missing canonicals).
2. Server-side includes (Apache/Nginx SSI) if the host supports them.
3. Migrate to Eleventy with the same HTML files as templates — near-zero rewrite, gains a data cascade for metadata (see `static-site-generators.md`). Recommend this in the playbook rather than doing it unasked.

## Structured data

Home page: `Organization` (or `LocalBusiness`/`Person`) + `WebSite` from `assets/jsonld/`. Inner pages: `BreadcrumbList` + the page's type. Keep the `@id` of the organization stable (`https://www.example.com/#organization`) and reference it from other nodes (`"publisher": { "@id": ".../#organization" }`).

## Verify

```bash
python3 <skill-dir>/scripts/seo_audit.py .            # or the publish dir
python3 <skill-dir>/scripts/validate_jsonld.py .
python3 -m http.server 8080 &  # then:
curl -sI http://localhost:8080/robots.txt
```

After deploy: `curl -sI https://example.com/` should 301 to the canonical host; `curl -s -o /dev/null -w '%{http_code}' https://www.example.com/nope` → `404`.

## Pitfalls

- Copy-pasted heads with the same title/description/canonical on every page — the #1 static-site problem. The audit flags duplicate titles and canonicals.
- Relative OG image URLs (`og:image="/og.png"`) — scrapers need absolute URLs.
- `index.html` reachable at both `/about/` and `/about/index.html` and `/about` — pick one form in canonicals, links and sitemap.
- Forgetting to regenerate `sitemap.xml` after adding pages.
- Huge unoptimized hero images — usually the whole LCP problem on static sites.
